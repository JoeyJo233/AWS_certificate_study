# Day 01：AWS 基础

学习日期：2026-09-30

## 1. Region（区域）与 AZ（可用区）

- Region：独立的地理区域，例如 `us-east-1`（美国东部·北弗吉尼亚）。
- AZ：区域内相互隔离的位置，包含一个或多个数据中心；一个区域有多个可用区。
- 跨 AZ 部署：应对一个可用区故障，还要配合流量分配、故障切换和足够的剩余容量。
- 应对整个区域故障：需要考虑跨 Region 灾备。
- **多台服务器放在同一个 AZ，仍可能因同一故障一起宕机。**

## 2. Shared Responsibility Model（共享责任模型）

- AWS 负责底层基础设施：数据中心门禁、硬件、虚拟化设施等。
- 客户负责自己的数据、权限、应用和相关配置；具体边界取决于服务。
- EC2（云服务器）：客户负责内部操作系统和应用的补丁，以及网络访问规则。
- RDS（托管关系型数据库）：AWS 承担更多维护工作；客户仍负责权限、网络、数据、容量及备份等配置。
- **托管减少维护负担，不代表客户没有责任。**

## 3. 身份与权限

- Authentication（身份认证）：确认“你是谁”。MFA（多因素认证）增强登录安全。
- Authorization（授权）：决定“你能做什么”。
- Principle of Least Privilege（最小权限原则）：只授予必要资源、必要操作的权限，需要结束后撤销。
- **启用 MFA 不代表应该获得管理员权限。**
- IAM（身份与访问管理）：User（用户）是身份；Role（角色）是可临时承担的身份；Policy（策略）描述允许或拒绝的操作。

## 4. 核心服务与数据访问

| 服务 | 用途 |
|---|---|
| EC2（云服务器） | 运行网站等程序 |
| S3（对象存储） | 保存图片、文件和备份等对象 |
| RDS（托管关系型数据库） | 保存并查询订单等结构化记录 |
| VPC（虚拟私有云） | 组织资源所在的网络及连接 |
| IAM（身份与访问管理） | 管理访问 AWS 资源的身份和权限 |

- S3：通过 Object Key（对象键）读取指定文件。
- 数据库：按字段筛选、排序、汇总，必要时用 JOIN（表连接）关联记录。
- Transaction（事务）：让一组数据库操作一起成功或一起撤销，例如创建订单和扣减库存；需要正确设计和使用。
- **选型看数据访问需求，不能根据数据在磁盘上是否零散来判断。** S3 也能可靠存储和支持并发访问。

## 5. 网络访问

- VPC（虚拟私有云）是网络空间；VPS（虚拟专用服务器）是一类服务器，两者不同。
- 数据库可放在 Private Subnet（私有子网），再通过 Security Group（安全组）限制只允许应用服务器连接所需端口。
- Public Subnet（公有子网）具有通向 Internet Gateway（互联网网关）的路由，资源不会因此自动对外开放。
- 互联网通过 IPv4（互联网协议第 4 版）直接访问 EC2，还需要公网地址、允许的路由和访问规则，以及正常监听的程序。
- Security Group、Network ACL（网络访问控制列表）和内部防火墙都不能阻断相关流量。
- **有密码不能替代网络访问限制；安全组不允许端口 443 的入站流量，就无法直接通过该端口访问 HTTPS（加密网页通信）。**

## 6. 高可用、伸缩与备份

| 概念 | 解决的问题 |
|---|---|
| High Availability（高可用） | 局部故障时仍能提供服务 |
| Scalability（可扩展性） | 能增加容量，承受更大业务量 |
| Elasticity（弹性） | 随需求增加或减少资源，减少闲置费用 |
| Backup（备份） | 恢复误删或损坏前的数据 |

- EC2 Auto Scaling（自动伸缩）可用于调整云服务器数量。
- **高可用副本不能替代备份：误删除也可能同步到其他副本。**
- 备份要考虑保留时间、恢复时间点，并验证能否成功恢复。

## 7. SAA（解决方案架构师助理认证）解题思路

- 四个方向：安全 30%、弹性与韧性 26%、高性能 24%、成本优化 20%。
- **先满足业务要求，再优化成本；最便宜或规模最大的方案不一定合适。**
- 每学一个服务，问：解决什么问题？何时适合？有什么代价？为什么不选其他方案？

# Day 04：VPC（虚拟私有云）与网络路径

学习日期：2026-09-30

## 1. VPC、子网与可用区

```text
Region（区域）
└─ VPC（虚拟私有云）：可以覆盖多个 AZ
   ├─ AZ A（可用区 A）
   │  ├─ 公有子网 → 网站 EC2
   │  └─ 私有子网 → 数据库
   └─ AZ B（可用区 B）
      └─ 另一个子网 → EC2
```

- 一个 VPC 属于一个 Region；一个 Subnet（子网）只能位于一个 AZ。
- 一个 AZ 可以有多个子网；不同子网不一定是不同 AZ。
- 跨 AZ 部署需要把实例放入不同 AZ 的子网，不能只看子网名称不同。
- 同 VPC、不同子网可以通过私有 IP 通信，但仍需网络规则放行。
- 不同 VPC 默认不能直接私网互通；可配置 VPC Peering（VPC 对等连接）等连接、双向路由和访问规则。对等连接的地址范围不能重叠。

## 2. CIDR（地址范围表示法）

IPv4 共 32 位，斜杠后的数字表示固定的前缀位数。**数字越大，地址范围越小。**

| 地址范围 | 包含的地址 | 地址总数 |
|---|---|---|
| 10.0.0.0/16 | 10.0.0.0～10.0.255.255 | 65,536 |
| 10.0.2.0/24 | 10.0.2.0～10.0.2.255 | 256 |
| 10.0.2.20/32 | 只有 10.0.2.20 | 1 |

- 每段数字只能是 0～255；256 是 /24 的地址数量，不是合法的末段值。
- 普通 AWS IPv4 子网保留 5 个地址；10.0.2.0/24 通常可分配 .4～.254，共 251 个。
- 子网范围必须属于 VPC 地址范围；同 VPC 的子网不能重叠，即使位于不同 AZ。
- 已有 10.0.2.0/24 时，不能再创建包含在其中的 10.0.2.0/25。
- 如果没有原来的 /24，可划分成 10.0.2.0/25（.0～.127）和 10.0.2.128/25（.128～.255）。

## 3. Route table（路由表）：流量往哪走？

**路由表是路牌，不是搬运数据的设备。** EC2 发出数据包，AWS 管理的虚拟网络按路由规则转发。

- 每个子网关联一张路由表；未显式指定时使用 Main route table（主路由表）。
- 多个子网可以共用一张路由表。
- Destination（目标范围）规定匹配哪些目标 IP；Target（下一站）规定往哪里转发。
- Longest prefix match（最长前缀匹配）：选择匹配目标地址、范围更具体的路由。
- 路由看这一包数据的目标，不看最初是谁发起业务请求；EC2 回复外部用户也需要返回路径。

私有子网的常见路由：

| 目标范围 | 下一站 |
|---|---|
| 10.0.0.0/16 | local（VPC 内部路由） |
| 0.0.0.0/0 | NAT Gateway（网络地址转换网关） |

访问 10.0.2.20：匹配 /16，比 /0 更具体，走 local；访问互联网地址：通常走 NAT。

## 4. 公有／私有子网与网关

| 概念 | 用途 |
|---|---|
| Public subnet（公有子网） | 有直接通向 IGW 的路由 |
| Private subnet（私有子网） | 没有直接通向 IGW 的路由，可通过 NAT 出网 |
| Internet Gateway，IGW（互联网网关） | 挂接到 VPC，连接互联网；不部署在某个子网或 AZ |
| Public NAT Gateway（公有 NAT 网关） | 替私有资源主动出网，转换地址；允许对应返回流量，不接受外部主动连入私有服务器 |

本节的 NAT 示例使用部署在公有子网中的 Zonal NAT Gateway（可用区级 NAT 网关），配置 Elastic IP（弹性公网 IP）。

```text
私有 EC2 → 公有子网中的 NAT Gateway → IGW → 互联网
```

- 私有子网：0.0.0.0/0 → NAT；NAT 所在公有子网：0.0.0.0/0 → IGW。
- 私有 EC2 无需自己的公有 IPv4 地址。
- 公有子网不等于资源公开：EC2 直接通过 IPv4 与互联网通信，还需公有地址、正确路由、安全规则和程序监听。
- 私有 IP 不能在公网直接路由到达，即使用户知道地址也不行。
- 没有公有 IP 的 EC2 可以通过 Internet-facing load balancer（面向互联网的负载均衡器）间接提供网站服务。
- 路由负责选路，Security group（安全组）负责放行；网络连通不等于获得 IAM（身份与访问管理）权限或数据库授权。

## 5. 完整例子：用户查看订单

```text
同一个 VPC：10.0.0.0/16
├─ 公有子网 → 网站 EC2：10.0.1.10，另有公有 IPv4 地址
└─ 私有子网 → 数据库：10.0.2.20

用户 ──网页请求──→ IGW → 网站 EC2 ──内部查询──→ 数据库
用户 ←──网页回复── IGW ← 网站 EC2 ←──查询结果── 数据库
```

1. DNS（域名系统）解析网站公有 IP；浏览器连接 TCP 443，发送 HTTPS（加密网页访问）请求。
2. 流量经过互联网和 IGW 到达 EC2；安全组允许 443，网站程序监听该端口。
3. 网站另行发起数据库连接，目标 10.0.2.20:3306；匹配 local 路由，不经过 NAT 或 IGW。
4. 数据库安全组允许网站来源的 3306 连接，应用通过数据库认证后查询订单。
5. 数据库回复目标为 10.0.1.10，走 local；网站回复用户公有 IP，走 0.0.0.0/0 → IGW。

**这是两条连接：用户 ↔ 网站、网站 ↔ 数据库，不是浏览器直接连接数据库。**

## 6. 安全组复习

- Inbound（入站）规则指定协议、端口和来源；Outbound（出站）规则指定协议、端口和目标。
- 数据库规则：允许 TCP 3306，来源为网站服务器的安全组；只限定端口、不限定来源仍不够。
- 只有 Allow（允许）规则；多个安全组的允许规则合并。
- Stateful（有状态）：已允许连接的返回流量自动放行，但仍需正确路由，其他网络规则也须满足。

## 7. NAT 与跨 AZ 故障

```text
AZ A 私有子网：0.0.0.0/0 → NAT A
AZ B 私有子网：0.0.0.0/0 → NAT B
```

- 每个 AZ 使用自己的可用区级 NAT，可减少跨 AZ 依赖及这段路径的跨 AZ 传输费用，但网关成本增加。
- 两边共用 NAT A：NAT A 故障会影响两边依赖它的出网路径；同 VPC 的 local 通信不因此必然失败。
- 有 NAT B 但路由仍指向 NAT A，不会自动改走 NAT B；闲置 NAT 仍产生费用。
- NAT A 单独故障、EC2 A 仍正常时，可把 A 子网路由改指 NAT B；已有连接可能需重建，可能增加跨 AZ 费用。
- 可用区级 NAT 的跨 AZ 路由切换默认不自动执行，可另行配置监控和自动化。
- 整个 AZ A 故障时，换 NAT 不能恢复已不可用的 EC2，需要其他 AZ 的应用资源接替。
